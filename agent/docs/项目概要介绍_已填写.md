# 企业数据底座智能问析 Agent 系统 项目概要介绍

## 1 引言

### 1.1 编写目的

本文档用于介绍企业数据底座智能问析 Agent 系统的项目背景、总体架构、功能模块、Agent 流程、接口设计、运行方式和错误处理机制，帮助评审人员、项目成员和后续开发人员快速理解系统的建设目标、技术路线与实现方法。

本系统面向制造企业数据底座，旨在让业务人员通过自然语言完成数据查询、统计分析、指标计算、异常检测、简单机器学习建模和报告生成，降低使用 SQL、Python 和数据分析工具的门槛，实现用户提问、智能分析、结果展示的闭环。
### 1.2 项目背景

制造企业在长期信息化建设中，通常已经形成生产工单、工序产量、质量检验、设备停机、库存等业务数据，并沉淀了数据表、字段说明、指标口径和表间关系。但业务人员往往不熟悉数据库、SQL、数据建模和 Python，难以直接使用这些数据完成自助分析。

传统模式下，业务人员需要向数据工程师提出需求，由数据工程师理解业务口径、查找数据表、编写 SQL 或 Python 代码，再将结果整理成图表和报告。这种方式响应周期长、重复工作多，并且容易出现业务口径不一致、字段理解错误和分析结果不可复用等问题。

大语言模型和 Agent 技术为数据底座智能问析提供了新的实现路径。本系统结合 LangChain、DeepSeek、RAG、Milvus 向量数据库、MySQL 数据库和 scikit-learn，构建面向企业数据底座的智能问析 Agent，使业务人员能够用自然语言直接发起分析任务。

## 2 系统总体设计

### 2.1 整体架构

系统整体采用数据层、知识层、Agent 层和展示层四层架构。

数据层以 MySQL 为核心，存储多表预置数据底座和业务数据。当前通过脚本从原始宽表 intelligent_production_iiot 拆分生成 dim_line、dim_machine、dim_product、dim_batch 和 fact_production_record 五张表，形成生产线、设备、产品、批次等维度与生产记录事实表之间的关联关系。

知识层负责数据资源理解和业务知识组织。metadata_service 负责读取 MySQL 表结构、字段类型、字段说明、样例值和表间关系，并输出 metadata JSON；knowledge_service 负责定义分析主题、业务对象、业务规则和指标口径，并将指标动态映射到真实表和字段。

Agent 层基于 LangChain 1.2.12 构建。EnterpriseAgent 负责统一问题路由，Text2SQLAgent 负责自然语言到 SQL 的生成与执行，RAG 模块负责检索相似问题与 SQL 示例，ReportGenerator 负责生成 Markdown 分析报告，modeling 模块负责异常检测和简单回归建模。

展示层目前以命令行入口 main.py 进行验证，后续计划接入 Spring Boot 后端和 Vue 或 React 前端，形成数据资源页、知识图谱页、智能问答页和分析结果页。
### 2.2 整体功能架构

系统功能分为六个核心模块。

第一，数据资源理解模块。动态读取 MySQL 表、字段、类型、主键、样例值和表间关系，并通过 metadata JSON 向前端和 Agent 暴露统一数据结构。

第二，业务知识管理与映射模块。定义分析主题、业务对象、业务规则和指标口径，例如缺陷率、良率、质量得分、停机时长、故障次数、产量和设备利用率，并将这些业务概念映射到实际数据表字段。

第三，自然语言智能分析模块。用户通过自然语言提出问题，系统理解问题后调用 SQL Agent 完成数据查询、分组统计、指标计算、趋势分析等任务。

第四，RAG 增强模块。使用 SiliconFlow 嵌入模型将问题和 SQL 示例向量化，写入 Milvus 向量数据库；用户提问时先检索相似问题与 SQL 示例，再注入 SQL Agent 提示词，提升 SQL 生成准确率。

第五，报告生成与可视化输出模块。SQL Agent 返回结构化的 SQL、列名、数据行和文字分析结论；ReportGenerator 可进一步生成 Markdown 分析报告，为前端图表展示和报告导出提供基础数据。

第六，建模与异常分析模块。基于 scikit-learn 实现 Isolation Forest 异常检测和 LinearRegression 简单回归预测，支持模型评估指标、特征系数和样本预测结果输出。
### 2.3 整体技术框架

系统核心技术栈如下。

- 后端与 Agent：Python 3.13、LangChain 1.2.12、langchain-community、langchain-deepseek、langchain-openai。
- 大语言模型：DeepSeek 对话模型，通过 langchain-deepseek 接入。
- 嵌入模型：SiliconFlow 提供的 BAAI/bge-m3 嵌入模型，通过 OpenAI 兼容接口调用。
- 向量数据库：Milvus，连接地址为 http://localhost:19530，数据库为 rag_dev，集合为 doc。
- 关系数据库：MySQL 8.0，数据库为 sqllangchain，多表预置底座包含 dim_line、dim_machine、dim_product、dim_batch、fact_production_record。
- 数据处理与建模：pandas、scikit-learn、SQLAlchemy、pymysql。
- 后续展示端计划：Spring Boot 后端、Vue 或 React 前端、ECharts 图表、知识图谱可视化。
- 环境管理：.env 统一管理模型、数据库、Milvus 和 RAG 配置，Python 虚拟环境为 sqllangchain。
### 2.4 运行环境设计

运行环境以 Windows 开发环境为主，MySQL 8.0 服务名为 MySQL80，Milvus 服务地址为 http://localhost:19530。Python 代码运行在 D:\Anaconda\envs\sqllangchain 虚拟环境中。

主要运行步骤包括：初始化多表预置底座、导出 metadata 与 knowledge JSON、导入 RAG 示例、启动命令行 Agent。初始化脚本可重复执行，会自动重建事实表并刷新 JSON 文件；RAG 示例导入脚本会重建 Milvus 集合 doc 并写入示例问题与 SQL。

系统配置项统一放在 .env 中，包括 DeepSeek API、SiliconFlow API、MySQL 连接、Milvus 连接和 RAG Top K 等参数，避免 API Key 和连接信息硬编码到代码中。
### 2.5 设计目标

系统设计目标包括六个方面。

第一，降低业务人员使用数据底座的门槛，让用户不需要掌握 SQL 和 Python 即可完成常见的生产、质量、设备分析。

第二，建立统一的数据资源理解能力，能够动态读取表结构与字段说明，并向前端和 Agent 提供一致的 metadata JSON。

第三，建立业务知识模型和映射关系，使缺陷率、良率、停机时长等业务指标能够准确映射到实际数据表字段，减少大模型臆造字段的问题。

第四，通过 RAG 检索相似问题与 SQL 示例，提高复杂业务问题生成 SQL 的准确率和稳定性。

第五，形成从自然语言提问、RAG 检索、SQL 生成、SQL 执行到文字结论、表格数据、Markdown 报告、异常检测和回归建模的完整闭环。

第六，保持代码结构模块化、配置集中化、流程可扩展，便于后续接入 Spring Boot、Vue 或 React 前端以及知识图谱页面。
### 2.6 Agent 流程搭建

系统 Agent 基于 LangChain 1.2.12 构建，整体流程分为问题接收、RAG 检索、上下文构建、SQL Agent 执行、结果提取与二次执行、结果路由六个阶段。

第一步，问题接收。用户通过 main.py 或后续接口输入自然语言问题，EnterpriseAgent.handle 方法接收问题并根据关键词进行路由。

第二步，RAG 检索。对于普通数据查询问题，Text2SQLAgent 在调用 SQL Agent 前先调用 get_rag_context，将用户问题通过 SiliconFlow BAAI/bge-m3 嵌入模型转为向量，在 Milvus 的 rag_dev 数据库 doc 集合中检索 Top K 个相似问题及参考 SQL。

第三步，上下文构建。系统从 metadata_service 获取表结构、字段说明、样例值和表间关系，从 knowledge_service 获取分析主题、业务对象、指标规则及字段映射，将 RAG 示例、metadata 上下文、业务指标口径和用户问题一起拼接为 SQL Agent 的输入提示词。

第四步，SQL Agent 执行。使用 LangChain 官方 create_sql_agent 创建 SQL Agent，agent_type 为 tool-calling。Agent 会自动选择 sql_db_list_tables、sql_db_schema、sql_db_query、sql_db_query_checker 等工具，完成表结构查看、SQL 生成、SQL 执行和错误重试。

第五步，结果提取与二次执行。Text2SQLAgent 开启 return_intermediate_steps，从 Agent 中间步骤中提取实际执行的 SQL，并使用只读 SQL 执行器重新执行该 SQL，得到列名、数据行和结构化结果。SQL 执行器只允许 SELECT 或只读 WITH 查询，避免误修改数据库。

第六步，结果路由。如果问题中包含报告关键词，则调用 ReportGenerator 生成 Markdown 分析报告；如果包含异常或离群关键词，则调用 IsolationForest 异常检测；如果包含预测或回归关键词，则调用 LinearRegression 回归建模；否则直接返回 SQL 查询结果和文字分析。
## 3 接口设计

### 3.1 接口设计原则

接口设计遵循统一路径、统一 JSON、职责分离和可扩展原则。

统一路径：后续 REST 接口统一以 /api/v1 为基础路径，按数据资源、知识模型、Agent 分析三部分划分。

统一 JSON：所有接口返回 JSON，统一包含 code、message、data 或直接返回业务数据结构，便于前端统一处理。

职责分离：metadata_service 只负责元数据读取与输出，knowledge_service 只负责知识模型与字段映射，EnterpriseAgent 只负责问题路由，Text2SQLAgent 只负责 SQL 生成与结构化结果，ReportGenerator 只负责报告生成。

可扩展：新增数据表、指标或模型时，优先扩展 metadata 和 knowledge 配置，而不是修改 Agent 主流程。
### 3.2 接口实现方式

当前 Python 层对外主要提供四类能力接口。

元数据接口：get_metadata_json 返回表、字段、样例值和表间关系，可扩展为 GET /api/v1/metadata/tables 和 GET /api/v1/metadata/relationships。

知识模型接口：resolve_knowledge 返回主题、对象、规则及其映射到真实表字段的结果，可扩展为 GET /api/v1/knowledge/overview 和 GET /api/v1/knowledge/graph。

Agent 问答接口：EnterpriseAgent.handle 接收问题并返回 type 与 result。type 为 agent 时返回 SQL、columns、rows、analysis_text 或 report；type 为 model 时返回异常检测或回归建模结果。后续可扩展为 POST /api/v1/agent/ask、POST /api/v1/agent/report、POST /api/v1/agent/anomaly、POST /api/v1/agent/regression。

RAG 接口：ingest_sql_examples 负责导入示例，search_sql_examples 负责相似检索，get_rag_context 负责将检索结果格式化为 Prompt 上下文。
## 4 运行设计

### 4.1 运行模块的组合

系统运行时由多个模块协同完成一次分析任务。

数据底座初始化阶段：init_preset_schema 从原始宽表生成维度表和事实表，并自动导出 metadata.json 与 knowledge.json。

RAG 初始化阶段：rag.ingest_examples 读取 sql_examples.json，调用 SiliconFlow 嵌入模型生成向量，写入 Milvus 的 rag_dev/doc 集合。

Agent 启动阶段：EnterpriseAgent 初始化 Text2SQLAgent、metadata、knowledge 和 RAG 检索能力。

用户分析阶段：EnterpriseAgent.handle 根据问题内容路由到 SQL Agent、报告生成、异常检测或回归建模。

结果输出阶段：CLI 打印文字结论、生成的 SQL、查询结果、RAG 检索示例和 Markdown 报告；后续前端可复用同样的结构化字段。
### 4.2 运行控制

运行控制主要通过命令行入口和环境变量完成。

命令行入口为 agent/main.py，启动后持续接收用户输入。输入 exit、quit 或 q 时退出。

初始化命令为 python -m scripts.init_preset_schema，用于初始化或重建多表预置底座并刷新 metadata 与 knowledge JSON。

RAG 导入命令为 python -m rag.ingest_examples，用于重建 Milvus 集合并导入问题-SQL 示例。

Agent 启动命令为 python main.py。运行前需要保证 MySQL80、Milvus 服务启动，并确保 .env 中 DeepSeek API、SiliconFlow API 和数据库配置正确。
## 5 系统出错设计

### 5.1 出错信息

系统对常见错误进行分类处理。

配置错误：缺少 DeepSeek API Key、SiliconFlow API Key 或数据库连接信息时，启动或调用阶段给出明确错误提示。

数据库连接错误：MySQL 未启动或连接失败时，提示无法连接数据库，并保留异常信息，便于排查。

SQL 生成错误：SQL Agent 生成的 SQL 可能不符合方言或字段不存在。create_sql_agent 会根据工具返回错误进行重试和修正；二次执行阶段也会捕获 SQL 异常并返回 error 字段。

SQL 安全校验：只读 SQL 执行器会拦截 INSERT、UPDATE、DELETE、DROP、ALTER、CREATE、TRUNCATE 等危险操作，只允许 SELECT 或只读 WITH 查询。

RAG 异常：Milvus 未启动、集合为空或嵌入 API 调用失败时，get_rag_context 返回空字符串，SQL Agent 流程继续执行，不影响主流程。

报告生成异常：ReportGenerator 调用失败时，返回基础分析结论作为降级内容。
### 5.2 系统维护设计

系统维护遵循配置与代码分离、元数据与知识模型分离、流程可替换的原则。

模型、数据库、Milvus 等配置统一放在 .env 中，修改环境不需要改代码。

元数据说明放在 metadata/preset_metadata.py，字段说明和表间关系可集中维护；实际表结构和样例值由 metadata_service 动态读取。

业务指标和知识映射放在 knowledge/knowledge_base.py，新增指标时增加候选字段和规则即可，避免在 Agent 中硬编码。

RAG 示例放在 rag/examples/sql_examples.json，新增示例后重新执行 rag.ingest_examples 即可刷新向量库。

系统使用 Git 进行版本管理，各功能模块独立提交，便于回滚和持续迭代。
## 6 项目解决的问题与采用方法

### 6.1 解决的核心问题

本项目主要解决以下核心问题。

第一，业务人员看不懂数据库表和字段，无法独立进行数据查询和分析。系统通过 metadata 服务自动读取表结构、字段说明和样例值，并通过知识模型将业务概念映射到实际字段。

第二，企业数据底座通常是一张或多张宽表，缺少清晰的维度与事实关系，不利于前端展示和知识图谱建设。系统通过脚本将原始宽表拆分为生产线、设备、产品、批次等维度表和一份生产记录事实表，建立明确的表间关系。

第三，业务指标口径容易写死，换数据源后字段名变化会导致大模型生成错误 SQL。系统使用 candidate_fields 候选字段列表和 resolve_metrics 动态匹配机制，根据当前真实字段解析可用指标，避免硬编码单个字段。

第四，大模型生成 SQL 容易产生字段臆造、语法错误或口径偏差。系统通过 metadata 上下文、业务知识映射、RAG 相似问题检索和 SQL Agent 工具循环共同提高生成准确率，并使用只读执行器保证安全。

第五，分析结果只停留在文字层面，难以直接生成报告或进行异常检测和预测。系统通过 AgentResult 返回 SQL、列名、数据行和文字结论，并在此基础上扩展 ReportGenerator、Isolation Forest 和 LinearRegression。

第六，项目后续需要接入前端和知识图谱，但缺少统一接口和数据结构。系统提前定义 metadata JSON、knowledge JSON 和 REST 接口设计文档，为后续 Spring Boot 与 Vue 或 React 接入预留接口。
### 6.2 采用的主要方法

第一，采用分层架构。数据层、元数据层、知识层、Agent 层和展示层职责清晰，方便逐步建设与扩展。

第二，采用 LangChain 官方 SQL Agent。使用 create_sql_agent 和 tool-calling 模式，让框架负责工具选择、SQL 生成、SQL 执行和错误重试，避免自行实现复杂 Agent 循环。

第三，采用 RAG 增强。先通过 SiliconFlow 嵌入模型和 Milvus 检索相似问题及参考 SQL，再和 metadata、知识规则一起注入提示词，提高复杂问题生成 SQL 的准确率。

第四，采用元数据驱动。所有表结构、字段说明、样例值和表间关系通过 metadata_service 统一读取和输出，Agent 和前端使用同一份元数据。

第五，采用知识模型驱动。将分析主题、业务对象、业务规则和指标口径抽象为知识模型，并通过 knowledge_service 映射到真实表字段，使业务知识真正影响 SQL 生成。

第六，采用结构化结果输出。AgentResult 同时返回 SQL、列名、数据行、文字结论和 RAG 上下文，便于前端展示表格、图表和报告。

第七，采用本地建模工具。使用 scikit-learn 实现 Isolation Forest 异常检测和 LinearRegression 回归预测，输出异常数量、异常记录、R2、RMSE 和特征系数等结果。

第八，采用配置分离与 Git 管理。大模型、数据库、Milvus 配置放在 .env 中，功能模块分阶段提交 Git，保证可维护、可回滚、可扩展。
### 6.3 项目创新点与应用价值

系统的主要创新点包括：一是将数据资源理解、业务知识映射和 RAG 检索结合到 SQL Agent 提示词中，形成元数据加知识加示例的三重增强；二是使用候选字段动态匹配机制解决业务指标与物理字段解耦问题；三是返回 SQL、列名、数据行和报告的结构化结果，便于前端和报告系统复用；四是预留知识图谱接口，为后续图谱化展示打基础。

应用价值方面，系统可以显著降低业务人员使用企业数据底座的门槛，让业务人员通过自然语言完成生产、质量、设备等常见分析；同时减少数据工程师重复编写 SQL 和整理报表的工作量，提高数据分析响应速度，并推动企业数据口径统一和知识沉淀。
## 7 总结与后续计划

当前系统已经完成多表预置底座、metadata 元数据读取与 JSON 导出、业务知识模型与字段映射、RAG 相似问题检索、LangChain SQL Agent、结构化结果返回、Markdown 报告生成、Isolation Forest 异常检测和 LinearRegression 回归建模。

后续计划主要包括：接入 Spring Boot 后端，将 Python Agent 能力封装为 FastAPI 或 REST 服务；接入 Vue 或 React 前端，实现数据资源页、知识图谱页、智能问答页和分析报告页；完善知识图谱节点与关系数据；增加更多机器学习模型，例如 KMeans、决策树和随机森林；增加图表自动生成、多轮对话、权限管理和分析历史记录等功能，最终形成完整的企业数据底座智能问析闭环。
